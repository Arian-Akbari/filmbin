# FilmBin — backend

سرویس اختصاصی پروژه (مدل پیشرفته، بخش ۷). اپلیکیشن موبایل هیچ‌وقت مستقیم با IMDb حرف نمی‌زند؛
همه چیز از این سرویس رد می‌شود.

```
اپلیکیشن موبایل  →  بک‌اند اختصاصی  →  IMDb
```

## راه‌اندازی

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env                 # اختیاری
.venv/bin/uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

مستندات تعاملی: <http://localhost:8000/docs> — و نسخهٔ خواندنی: `/redoc`.

### اجرای امن (HTTPS + پین‌کردن گواهی)

```bash
./scripts/generate_certs.sh                     # CA خصوصی + گواهی سرور
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8443 \
    --ssl-certfile certs/server.crt --ssl-keyfile certs/server.key
```

اسکریپت اثر انگشت `SHA-256` گواهی را چاپ می‌کند؛ همان مقدار را موقع اجرای اپلیکیشن با
`--dart-define=PINNED_CERT_SHA256=<اثر انگشت>` بدهید تا فقط همین سرور پذیرفته شود. مقدار در
`app/lib/core/config/app_config.dart` خوانده و در `core/network/certificate_pinning.dart` بررسی می‌شود.

### ابزار مدیریتی

```bash
.venv/bin/python scripts/manage.py create-admin --email admin@filmbin.ir --password 'Str0ngPass!'
.venv/bin/python scripts/manage.py seed          # پر کردن حافظهٔ محلی با آثار محبوب
.venv/bin/python scripts/manage.py purge-cache
```

## آزمون‌ها

```bash
.venv/bin/pytest            # ۱۱۵ آزمون آفلاین با IMDb ساختگی
.venv/bin/pytest -m live    # ۳ آزمون قراردادی روی IMDb واقعی
```

آزمون‌ها اول نوشته شدند و بعد پیاده‌سازی — هر بخش از صورت پروژه دست‌کم یک آزمون دارد.

## ساختار

```
app/
  core/      تنظیمات، امنیت (bcrypt + JWT)، قالب خطا، محدودیت نرخ، وابستگی‌ها
  db/        موتور SQLAlchemy و مدل‌های پایگاه داده
  imdb/      کوئری‌های GraphQL، کلاینت مقاوم، نگاشت داده، لایهٔ کش
  schemas/   قراردادهای ورودی/خروجی (Pydantic)
  services/  منطق دامنه: پیشرفت تماشا، آمار، پیشنهادها، فعالیت‌ها
  api/       مسیرها، دسته‌بندی‌شده بر اساس حوزه
tests/       آزمون‌ها + IMDb ساختگی
scripts/     گواهی TLS و ابزار مدیریتی
```

## چند تصمیم مهم

**چرا GraphQL عمومی IMDb؟** خود IMDb همین نقطهٔ پایانی را برای وب‌سایتش استفاده می‌کند؛
بدون کلید کار می‌کند و همهٔ چیزی که پروژه می‌خواهد را دارد: جست‌وجوی پیشرفته، جزئیات اثر،
فصل‌ها و قسمت‌ها، بازیگران و جدول‌های محبوبیت. کوئری‌ها در `app/imdb/queries.py` جمع‌اند تا
تعویض سرویس اطلاعاتی فقط یک فایل را درگیر کند (بخش ۸.۶).

**چرا آینهٔ محلی؟** هر پاسخ IMDb در پایگاه دادهٔ خودمان ذخیره می‌شود. نتیجه: درخواست تکراری
به بیرون نمی‌رود، پاسخ‌ها سریع‌ترند و اگر IMDb قطع شود سرویس با دادهٔ ذخیره‌شده کار می‌کند
(بخش‌های ۷.۵ و ۸.۴). یک «مدارشکن» هم بعد از چند خطای پیاپی جلوی درخواست‌های بی‌فایده را می‌گیرد.

**چرا وضعیت تماشا و علاقه‌مندی جدا هستند؟** صورت پروژه «موردعلاقه» را هم در فهرست وضعیت‌ها
آورده و هم به‌عنوان فهرست جداگانه. در عمل کاربر می‌تواند هم‌زمان «در حال تماشا» و «موردعلاقه»
داشته باشد، پس وضعیت یک `enum` است و علاقه‌مندی یک پرچم مستقل.

**رنگ نوار پیشرفت روی سرور حساب می‌شود** تا همهٔ کلاینت‌ها یک چیز نشان دهند:
بی‌رنگ (شروع‌نشده)، زرد (قسمت دیده‌نشده دارد)، سبز (به‌روز ولی سریال ادامه دارد)،
بنفش (تمام‌شده) و قرمز (کاربر وسط کار متوقف شده).

## نکتهٔ امنیتی

`EXPOSE_RESET_TOKEN=true` توکن بازیابی رمز را در پاسخ HTTP برمی‌گرداند تا بشود بدون سرور ایمیل
جریان را تست کرد. در نسخهٔ واقعی باید `false` باشد و توکن با ایمیل برود.
